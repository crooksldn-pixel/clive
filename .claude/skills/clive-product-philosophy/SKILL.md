# CLIVE Product Philosophy

Design rules:
- show what is needed when it is needed, nothing more;
- answer first; UI supports rather than overwhelms;
- progressive disclosure beats telemetry walls;
- authority remains with the person entitled to decide;
- capable systems should handle routine responsibility themselves;
- proposed, authorised, started, completed and verified are different states;
- never present a guess as live truth;
- don't ask George to relay mechanical work the system can do;
- interrupt for genuine owner decisions, not ordinary engineering failures;
- preserve reversibility and explicit deployment authority;
- hidden complexity is acceptable only when it reduces visible complexity.

For every owner-visible proposal ask:
- what decision/action does George actually need now?
- what can remain hidden?
- what evidence makes the state trustworthy?
